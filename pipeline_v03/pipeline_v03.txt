## 0. 연구자가 갖고 있어야 하는 파일

---

- RAW_DATA
- PROCESSED_DATA
- 연구 계획서 (Word .docx 권장 — 수식을 자동으로 읽을 수 있음)
- 장비 사양 보고서
- 최종 보고서 초안 (연구 자료와 다른 경로로 입력)

## 1. Ingest

---

1. 입력 격리·분류 [Python]
    1. 경로 격리: 입력된 파일의 사본만 받아 읽기 전용으로 잠근다. 산출물은 입력 밖 폴더에 생성한다.
    최종 보고서 초안은 다른 경로로 입력 받고, Validate 전까지 열지 않는다(원본 해시만 기록).
    2. 유형 분류: 각 파일이 raw_data인지, processed_data인지, 연구 계획서인지, 장비 사양 보고서인지 분류한다. 스크립트·그림·메모는 목록에만 남기고 실행하지 않는다.
    3. 필요 파일 점검: 0번의 5종이 모두 있는지 점검표로 남긴다. RAW·계획서가 없으면 진행을 막는다.
2. 지문·시각 기록 [Python]
    1. 해시 2종: 한 파일은 원본 바이트 해시 1개와 내용 정규화 해시 1개로 총 2개의 해시를 갖는다. 이에 따라, 다른 파일과 구분할 수 있고, 변경 시에 행·열 차이(바뀜·추가·빠짐과 줄 번호)를 파악할 수 있다. 바이트만 다르고 내용이 같으면 '형식만 변경'으로 본다.
    2. 측정 시각: 파일마다 (1) 파일 수정 시각, (2) 장비가 기록한 시각 두 가지 종류를 모은다. 파일 수정 시각은 복사만 하여도 달라질 수 있으므로, 장비 헤더 시각이 있다면 그걸 우선한다.
        1. 원본 파일의 수정 시각은 사본에 옮겨 둔다. 원본 시각을 받지 못한 업로드(웹)는 업로드 시각이므로 측정 시각으로 쓰지 않는다.
        2. 파일 수정 시각이 마지막 장비 기록 시각보다 이르면 확인 항목으로 남긴다.
3. 계획서 수식 추출 [Python]
    1. Word 계획서의 수식(OMML)을 LaTeX로 바꾼다. LLM은 쓰지 않는다(변환기 dwml).
    2. 수식마다 번호(EQ01, EQ02, …)와 바로 앞 문장, 수식 해시, 파일 해시를 함께 남긴다.
    3. 수식 하나가 변환에 실패해도 그 수식만 '실패'로 남기고 나머지는 계속한다. 실패한 수식은 Confirm에서 연구자에게 직접 입력받는다.
    4. Word가 아닌 계획서(PDF 등)는 수식을 자동으로 읽지 않음을 알린다.
4. 파생 이력 기록 [Python]
    1. Lineage: (입력 해시, 함수 버전, 파라미터) → 출력 해시
    2. "입력 해시 + 함수 버전 + 파라미터 → 출력 해시"를 기록하는 장부를 여는 단계이다. 이후 파이프라인이 만드는 모든 중간 산출물이 여기 한 줄씩 적힌다. 참고로 연구자가 폴더에 넣어 온 가공 파일은 파이프라인 밖에서 만들어졌으니까 파생 기록이 없다.
    3. '파생'은 파일 생성의 줄임말이 아니라, 파이프라인이 만든 산출물이 어떤 입력·어떤 코드·어떤 파라미터에서 나왔는지를 뜻한다. 세 가지가 같으면 출력 해시도 같아야 재현된 것이다.

## 2. Extract

---

1. 입력 데이터 분석
    1. 데이터 내용 파악 [LLM] — 각 데이터 파일(RAW·PROCESSED)이 어떤 것을 의미하는지 탐색한다. 같은 열 구성의 파일끼리 묶고, LLM에는 열 이름과 문자 값만 보낸다(측정값 숫자는 보내지 않음).
    2. 연구 내용 추출
        1. 이론·수식·계산 과정 추출 [LLM]
            1. 수식 자체는 Ingest에서 파이썬이 뽑은 LaTeX를 쓴다. LLM은 각 식의 뜻·변수 ↔ 데이터 열·역할만 설명하고, 변환 실패한 식은 지어내지 않는다.
            2. raw → 보고값까지의 계산 과정(단계)과 실험 설계·검정 방법·보고할 값 목록을 뽑는다.
            3. 계산식을 파악해서 계산용 python 코드를 작성한다. RAW와 PROCESSED를 따로 받으며(compute(raw, processed)), 보고값은 RAW에서만 계산한다. 이 단계에서는 실행하지 않고 금지 항목만 정적 점검한다.
        2. 실험 ↔ 데이터 ↔ 식 ↔ 장비를 매칭한다. 계산 과정이나 매칭이 비어 있으면 한 번 다시 묻는다.
        3. 첨언: 우리의 Agent AI가 연구실이 계산할 때 사용하는 코드에 직접 접근할 수 없으므로, 연구자가 계획서에 계산식을 정확하게 적었을 것이라고 신뢰한다. 만약 연구자가 스스로 사용하는 계산 코드가 있다면, Recompute 단계에서 직접 넣어서 해도 되고, 본인이 두 실험 결과를 비교해도 된다. (연구자 코드 넣기는 아직 미구현)
2. 측정 조건 추출 [LLM → Python]
    1. 장비 사양 PDF 확인 — 결과의 측정 범위, 오차(정확도), 유효한 값의 범위, 범위 밖 표시값, 동작 조건(온도·예열 시간 등)을 파악한다.
        1. 뽑은 값마다 근거 문장과 쪽 번호를 받고, 그 문장이 원문에 있는지·값의 숫자가 문장 안에 있는지 파이썬이 확인한다.
        2. 이상치 판단 기준(유효 범위)은 현재 단계에서 정하되, 물어보는 것은 Confirm 단계에서 진행한다.
3. 데이터 구조화 — Raw/Processed_DATA 읽는 단계이다.
[LLM + Python]
    1. 데이터 내용 파악 — csv 파일 안에 어떤 내용을 담고 있는지 파악한다(1-1의 열 역할·단위 사용).
    2. 내용을 파악하여 단위 누락, 모호한 단위, 누락 데이터, 숫자가 아닌 값, 이상치(장비 사양 범위 밖 값·범위 밖 표시값) 확인을 진행한다. 파일·열·줄 번호·값까지 남긴다. 통계적으로 튀는 값은 판정하지 않는다.
4. 누락 점검 [LLM → Python]
    1. 연구 계획서와 비교하여 결론을 도출하기 위해서 필요한 파일이 다 있는지 점검한다. LLM은 계획서만 읽고 필요한 시료·반복·측정점 수를 뽑고, 실제 파일과의 대조는 파이썬이 한다.

## 3. Confirm

---

1. 데이터 해석 승인
Extract 1 실행 결과를 물어보고, Extract 4 실행한 후 누락된 것을 파악하여 물어본다.
    1. 질문 1: Extract 1에서 한 것을 물어본다.
    (예시) 수식 A를 사용하여, 다음과 같이 계산한 게 맞나요?
    이 실험에서 장비 Z를 활용하여 측정값 K를 확인한 게 맞나요?
     실험 ↔ 데이터 ↔ 식 ↔ 장비를 이렇게 사용한 게 맞나요? <관계를 도식(Mermaid·글)으로 함께 보여 준다.>
    이 계산 코드로 계산해도 되나요? <승인하면 코드 해시를 고정한다.>
        1. LLM이 잘못 이해했다면, 어떤 부분을 고쳐야 하는지 입력 받는다. 이후, Extract로 돌아가서 다시 진행하고, 제안이 바뀐 항목만 다시 묻는다. 최대 3회까지 하고, 그래도 아니면 미확정으로 남긴다.
        2. 변환에 실패한 수식은 원문을 보고 LaTeX로 직접 입력받는다.
        3. 계산 과정·매칭이 비어 있으면 '맞음'을 고를 수 없고 고칠 내용을 입력받는다.
2. 분석 범위 확정
Extract 2 실행 결과를 물어본다.
    1. 질문: Extract 2에서 한 것을 물어본다.
    (예시) 장비 사양 보고서 n쪽을 읽어보니, 측정 조건 ɑ에서 오차 n% 라고 나오는데, 맞게 읽었나요?
        1. LLM이 잘못 읽었다면, 어떤 부분을 어떻게 고쳐야 하는지 입력받는다. 이후, Extract로 돌아가서 다시 진행한다.
3. 측정 기준 승인
Extract 3 실행 결과를 물어본다.
    1. 질문: 장비 사양 보고서에 따르면 측정 조건 β에서 오차 범위 m% 라고 넣었는데, raw_data.csv 파일을 읽었는데 n번 행 / k번 열에서 이 조건을 위반합니다.
        1. 단위 누락, 모호한 단위: 단위를 제안하고, 사용자의 입력도 받을 수 있다. RAW와 PROCESSED에 같은 이름의 열이 있으면 따로 묻는다.
        2. 결측치, 이상치: 유저가 파일을 확인 후 재업로드한 뒤, Ingest로 돌아간다. 값이 맞다고 확인하면 그대로 진행하되 기록(E02)을 남긴다.
        3. 측정 시각: 장비 기록 시각과 파일 수정 시각 중 무엇을 썼는지 확인한다.

## 4. Recompute

---

1. 수치 재계산
    1. 최종 값을 구하기 위해서는 여러 중간 단계가 필요할 것이다. 각 중간 단계에서는 식이 여러 개 있을 것이고, 각 식은 독립 변수가 다를 것이다. 이를 위해서
        - Extract_1_b에서 추출한 계산 과정 식
        - 사용자로부터 Confirm 받은 식
        - 실험 ↔ 데이터 ↔ 식 ↔ 장비 中 데이터 ↔ 식
        
        을 활용하여 수치를 재계산한다.
        
    2. 실행 전 확인: 승인한 코드 해시, 추출 결과가 승인 때와 같은지, 데이터 해시, 금지 항목을 확인한다. 하나라도 어긋나면 계산하지 않는다.
    3. 승인한 코드는 격리된 환경에서 한 번 실행한다(파일 쓰기·네트워크·허용 밖 읽기 차단, 시간 제한).
    4. PROCESSED 확인
        1. 독립성: PROCESSED를 빼고 한 번 더 계산해, 값이 바뀌는 결과는 'RAW로 재현되지 않음'으로 표시한다(연구자 숫자로 연구자 숫자를 검증하지 않기 위해).
        2. 대조: PROCESSED 파일에 적힌 값을 RAW로 다시 계산한 값과 적힌 자릿수로 비교해 다른 값을 파일·줄 번호로 남긴다.
    5. 계산 로그 생성
        1. 계산 로그를 작성한다. 계산 로그에 작성할 정보는 다음 4개이다.
            - 우리가 사용한 data의 해시 값 2종 (RAW·PROCESSED 파일마다, 그리고 묶음 전체)
            - 계산 과정 (확정한 식의 LaTeX·계산 단계·코드 해시·중간값)
            - 진짜 결과 값 그 자체 (반올림 전)
            - 결과 값에 대한 해시
        2. 계산 로그에 작성할 정보는 다음과 같다.
        우리의 계산이 어떠한 파일을 바탕으로 도출한 값인지 기록하기 위해, 사용한 raw/processed_data의 해시 값을 저장해놓는다. 추후, 새로운 data 파일이 들어온다면, 우리가 계산에 활용한 해시 값과 비교하여 최신화된 파일인지 그 여부를 파악할 수 있다. 같은 프로젝트를 다시 돌리면 이전 계산과의 데이터 변경(E07)도 기록한다.
    
## 5. Validate

---

1. 최종 보고서 초안 문장(주장) 추출 [LLM]
    1. 보고서는 재계산이 끝난 뒤에 처음 연다. LLM에는 재계산 값을 보내지 않는다(항목 이름·단위만).
    2. 연구자가 정한 실험 설정값(인가 전압 범위 등)은 주장으로 뽑지 않는다.
2. Recompute 결과와 비교 [Python]
    1. 출력할 때, 페이지 번호와 문장 번호를 직접적으로 입력하며 가독성을 높인다.
    2. 보고서에 적힌 자릿수로 반올림해 비교하고, 단위 환산·방향·유의성·표본 수·자유도를 확인한다. 재계산 항목이 없는 개수(n) 주장은 계획서의 수(시료 수·반복 수·측정점 수)와 비교한다.
3. 오류 코드 분류 — 수정하기
    1. E01 단위 불일치 (누락 포함)
    2. E02 측정값 이상 — 사양 범위 밖 값을 연구자가 확인하고 진행 (기록만)
    3. E03 필요 데이터 누락 — 그 집단을 쓰는 주장에만
    4. E04 표본 수·자유도 불일치
    5. E05 수치·방향·유의성 불일치
    6. E06 재계산 근거 없음·미확정 (RAW로 재현되지 않은 결과 포함)
    7. E07 데이터 버전 변경 (기록만)

## 6. Audit

---

1. Validate 결과 출력
    1. Supported 항목 나열. 논문 문장을 추출하여 우리가 recompute를 통해 계산한 값을 비교하여 보여준다.
    2. Unsupported 항목 나열. 논문 문장을 추출하여 우리가 recompute를 통해 계산한 값을 비교하여 보여준다.
    3. 재계산 결과 표, 데이터·결과 해시, PROCESSED 대조 결과를 함께 보여준다.
2. 수정 후 재평가
    1. 사용자가 Unsupported 된 항목을 수정하고 다시 MeasureTrace를 돌렸을 때 수정 전·후를 비교하여서 재평가한다 (고쳐짐·나빠짐·그대로·새 주장·사라짐)
