## 0. 연구자가 갖고 있어야 하는 파일

---

- RAW_DATA
- PROCESSED_DATA
- 연구 계획서
- 장비 사양 보고서
- 최종 보고서 초안

## 1. Ingest

---

1. 입력 격리·분류 [Python]
    1. 경로 격리: 입력된 파일을 읽기만 한다. 산출물은 입력 밖 폴더에 생성한다.
    최종 보고서 초안은 다른 경로로 입력 받는다. 물리적으로 다른 폴더에 받아도 괜찮다.
    2. 유형 분류: 각 파일이 raw/processed_data인지, 실험 계획서인지, 장비 사양 보고서인지 분류한다.
2. 지문·시각 기록 [Python]
    1. 해시 2종: 한 파일은 원본 바이트 해시 1개와 내용 정규화 해시 1개로 총 2개의 해시를 갖는다. 이에 따라, 다른 파일과 구분할 수 있고, 변경 시에 행·열 차이를 해시 값을 통해 파악할 수 있다.
    2. 측정 시각: 파일마다 (1) 파일 수정 시각, (2) 장비가 기록한 시각 두 가지 종류를 모은다. 파일 수정 시각은 복사만 하여도 달라질 수 있으므로, 장비 헤더 시각이 있다면 그걸 우선한다.
3. 파생 이력, 기록 — *파생이라는 게 무슨 말인가? 설마 파일 생성의 줄임말인가?*  [Python]
    1. Lineage: (입력 해시, 함수 버전, 파라미터) → 출력 해시
    2. "입력 해시 + 함수 버전 + 파라미터 → 출력 해시"를 기록하는 장부를 여는 단계이다. 이후 파이프라인이 만드는 모든 중간 산출물이 여기 한 줄씩 적힌다. 참고로 연구자가 폴더에 넣어 온 가공 파일은 파이프라인 밖에서 만들어졌으니까 파생 기록이 없다.

## 2. Extract

---

1. 입력 데이터 분석
    1. 데이터 내용 파악 — 각 데이터 파일이 어떤 것을 의미하는 지 탐색한다.
    2. 연구 내용 추출
        1. 이론·수식·계산 과정 추출
            1. 계산식을 파악해서 계산용 python 코드를 작성한다.
        2. 실험 ↔ 데이터 ↔ 식 ↔ 장비를 매칭한다.
        3. 첨언: 우리의 Agent AI가 연구실이 계산할 때 사용하는 코드에 직접 접근할 수 없으므로, 연구자가 계획서에 계산식을 정확하게 적었을 것이라고 신뢰한다. 만약 연구자가 스스로 사용하는 계산 코드가 있다면, Recompute 단계에서 직접 넣어서 해도 되고, 본인이 두 실험 결과를 비교해도 된다.
2. 측정 조건 추출
    1. 장비 사양 PDF 확인 —결과의 정산 범위, 오차, 유효한 값의 범위를 파악한다.
        1. 이상치인지 아닌지 판단하는 것은 현재 단계에서 하되, 물어보는 것은 Confirm 단계에서 진행한다.
3. 데이터 구조화 — Raw/Pocessed_DATA 읽는 단계이다.
[LLM + Python]
    1. 데이터 내용 파악 — csv 파일 안에 어떤 내용을 담고 있는지 파악한다.
    2. 내용을 파악하여 단위 누락, 모호한 단위, 누락 데이터, 이상치 확인을 진행한다.
4. 누락 점검 [LLM]
    1. 연구 계획서와 비교하여 결론을 도출하기 위해서 필요한 파일이 다 있는지 점검한다.

## 3. Confirm

---

1. 데이터 해석 승인
Extract 1 실행 결과를 물어보고, Extract 4 실행한 후 누락된 것을 파악하여 물어본다.
    1. 질문 1: Extract 1에서 한 것을 물어본다.
    (예시) 수식 A를 사용하여, 다음과 같이 계산한 게 맞나요?
    이 실험에서 장비 Z를 활용하여 측정값 K를 확인한 게 맞나요?
     실험 ↔ 데이터 ↔ 식 ↔ 장비를 이렇게 사용한 게 맞나요? <도식화하여 관계를 유기적으로 보여도 될 것 같다.>
        1. LLM이 잘못 이해했다면, 어떤 부분을 고쳐야 하는지 입력 받는다. 이후, Extract로 돌아가서 다시 진행한다.
2. 분석 범위 확정
Extract 2 실행 결과를 물어본다.
    1. 질문: Extract 2에서 한 것을 물어본다.
    (예시) 장비 사양 보고서를 읽어보니, 측정 조건 ɑ에서 오차 n% 라고 나오는데, 맞게 읽었나요?
        1. LLM이 잘못 읽었다면, 어떤 부분을 어떻게 고쳐야 하는지 입력받는다. 이후, Extract로 돌아가서 다시 진행한다.
3. 측정 기준 승인
Extract 3 실행 결과를 물어본다.
    1. 질문: 장비 사양 보고서에 따르면 측정 조건 β에서 오차 범위 m% 라고 넣었는데, raw_data.csv 파일을 읽었는데 n번 행 / k번 열에서 이 조건을 위반합니다.
        1. 단위 누락, 모호한 단위: 단위를 제안하고, 사용자의 입력도 받을 수 있다.
        2. 결측치, 이상치: 유저가 파일을 확인 후 재업로드한 뒤, Ingest로 돌아간다

## 4. Recompute

---

1. 수치 재계산
    1. 최종 값을 구하기 위해서는 여러 중간 단계가 필요할 것이다. 각 중간 단계에서는 식이 여러 개 있을 것이고, 각 식은 독립 변수가 다를 것이다. 이를 위해서
        - Extract_1_b에서 추출한 계산 과정 식
        - 사용자로부터 Confirm 받은 식
        - 실험 ↔ 데이터 ↔ 식 ↔ 장비 中 데이터 ↔ 식
        
        을 활용하여 수치를 재계산한다.
        
    2. 계산 로그 생성
        1. 계산 로그를 작성한다. 계산 로그에 작성할 정보는 다음 4개이다.
            - 우리가 사용한 data의 해시 값 2종
            - 계산 과정
            - 진짜 결과 값 그 자체
            - 결과 값에 대한 해시
        2. 계산 로그에 작성할 정보는 다음과 같다.
        우리의 계산이 어떠한 파일을 바탕으로 도출한 값인지 기록하기 위해, 사용한 raw/processed_data의 해시 값을 저장해놓는다. 추후, 새로운 data 파일이 들어온다면, 우리가 계산에 활용한 해시 값과 비교하여 최신화된 파일인지 그 여부를 파악할 수 있다.
    
    ## 5. Validate
    
    ---
    
    1. 최종 보고서 초안 문장(주장) 추출
    2. Recompute 결과와 비교
        1. 출력할 때, 페이지 번호와 문장 번호를 직접적으로 입력하며 가독성을 높인다.
    3. 오류 코드 분류 — 수정하기
        1. 단위 불일치 (누락 포함)
    
    ## 6. Audit
    
    ---
    
    1. Validate 결과 출력
        1. Supported 항목 나열. 논문 문장을 추출하여 우리가 recompute를 통해 계산한 값을 비교하여 보여준다.
        2. Unsupported 항목 나열. 논문 문장을 추출하여 우리가 recompute를 통해 계산한 값을 비교하여 보여준다.
    2. 수정 후 재평가
        1. 사용자가 Unsupported 된 항목을 수정하고 다시 MeasureTrace를 돌렸을 때 수정 전·후를 비교하여서 재평가한다
